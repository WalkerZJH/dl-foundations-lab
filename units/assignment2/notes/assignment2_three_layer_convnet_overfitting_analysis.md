# ThreeLayerConvNet 泛化问题补充分析

## 1. 快速结论

在 Assignment 2 的 `ThreeLayerConvNet` 实验中，小数据设置下出现了明显的 train-test gap：训练准确率为 `0.852`，测试准确率为 `0.400`。这一现象说明模型在 2000 张训练图像上拟合较充分，但对验证集和测试集的泛化不足。

需要说明的是，`train=2000, val=500, test=500` 是本仓库在 Assignment 2 中沿用的 CS231n 快速验证口径，主要用于在较短时间内检查代码补全、梯度实现和训练流程是否正确。它不应直接等同于完整 CIFAR-10 训练设置下的最终性能。

为判断该现象是否主要由训练子集过小导致，我额外运行了一组完整训练数据诊断实验。在保持模型结构和主要超参数不变的情况下，将训练集扩大到 `train=49000`，测试准确率从 `0.400` 提升到 `0.611`，full train-test gap 降低到约 `0.119`。这说明原先看似严重的过拟合，很大程度上与快速验证子集的数据规模有关。

本文档作为补充归档，不替换 Assignment 2 的主结果表。它的目的不是说明模型已经被充分优化，而是记录一次针对泛化问题的诊断过程。

## 2. 小数据主实验结果

`ThreeLayerConvNet` 的网络结构为：

```text
conv - relu - 2x2 max pool - affine - relu - affine - softmax
```

小数据主实验配置如下：

```text
train = 2000
val = 500
test = 500
optimizer = adam
learning_rate = 1e-3
epochs = 10
batch_size = 100
num_filters = 8
filter_size = 3
hidden_dim = 100
weight_scale = 1e-2
reg = 1e-3
```

结果如下：

| 设置         | Train Acc | Best Val Acc | Test Acc | Train-Test Gap | Final Loss |
| ------------ | --------- | ------------ | -------- | -------------- | ---------- |
| 小数据主结果 | 0.852     | 0.462        | 0.400    | 0.452          | 0.4084     |

从结果看，模型并非没有学习能力。训练准确率较高，loss 也已经下降，说明前向传播、反向传播和优化流程基本有效。问题主要在于训练集表现明显高于验证集和测试集表现，即模型在当前小训练子集上出现了泛化不足。

需要注意，当前 `Solver` 记录的训练准确率通常是从训练集中抽样估计得到的，不一定是全量训练集准确率。因此，单个数值不宜过度解释；但 train、val、test 之间的明显差距仍然能够支持泛化不足的判断。

## 3. 原因分析

首先，训练集规模较小。2000 张 CIFAR-10 训练图片不足以覆盖自然图像分类中的多样变化，模型容易学到训练子集中的局部纹理、颜色分布、背景模式或样本偶然特征。

其次，模型容量相对于小训练集并不低。在 `num_filters=8`、`hidden_dim=100` 时，参数主要集中在池化后的全连接层：

```text
W1: 8 * 3 * 3 * 3 = 216
W2: 8 * 16 * 16 * 100 = 204800
W3: 100 * 10 = 1000
```

总参数量约 20.6 万。相对于 2000 张训练图片，这一容量足以较强地拟合训练子集。

再次，当前基础实验没有使用数据增强，也没有额外加入 BatchNorm、Dropout 或 early stopping。L2 正则可以限制权重过大，但不能直接增加样本多样性，因此在小数据设置下不一定足以解决泛化问题。

因此，小数据主结果中的 train-test gap 更适合解释为“快速验证子集上的泛化不足”，而不是简单解释为代码实现失败。

## 4. 正则化与降容量 probe

为了判断简单调整是否能够改善测试表现，我额外进行了三组 probe。它们保持数据规模、训练轮数、优化器和学习率不变，只调整 L2 正则强度、卷积核数量或隐藏层维度。

| 设置                                                         | Train Acc | Best Val Acc | Test Acc | Train-Test Gap |
| ------------------------------------------------------------ | --------- | ------------ | -------- | -------------- |
| 小数据主结果：filters=8, hidden=100, reg=1e-3                | 0.852     | 0.462        | 0.400    | 0.452          |
| stronger L2：filters=8, hidden=100, reg=1e-2                 | 0.872     | 0.442        | 0.390    | 0.482          |
| lower capacity + stronger L2：filters=4, hidden=100, reg=1e-2 | 0.758     | 0.432        | 0.368    | 0.390          |
| smaller hidden + stronger L2：filters=8, hidden=50, reg=1e-2 | 0.746     | 0.418        | 0.392    | 0.354          |

这三组调整都没有超过小数据主结果的测试准确率。其中，降低模型容量虽然缩小了 train-test gap，但测试准确率没有提升。这说明 gap 变小不一定代表模型真正变好，也可能只是模型对训练集和测试集都学得更弱。

因此，这几组 probe 的结论是：在 `train=2000` 的快速验证设置下，单点增大 L2 或简单降低容量不足以解决泛化问题。

## 5. 完整训练数据诊断实验

为了进一步判断小数据规模对结果的影响，我补充运行了一组完整训练数据实验。该实验保持模型结构和主要超参数不变，只扩大训练数据规模。

完整训练数据实验配置如下：

```text
train = 49000
val = 1000
test = 1000
optimizer = adam
learning_rate = 1e-3
epochs = 10
batch_size = 100
num_filters = 8
filter_size = 3
hidden_dim = 100
weight_scale = 1e-2
reg = 1e-3
```

其中，`train=49000` 表示使用 CIFAR-10 训练集中除验证集外的样本；`test=1000` 沿用本仓库当前实验脚本中的轻量测试口径，用于控制实验成本。

结果如下：

| 设置                            | Sampled Train Acc | Full Train Acc | Best Val Acc | Test Acc | Full Train-Test Gap | Final Loss |
| ------------------------------- | ----------------- | -------------- | ------------ | -------- | ------------------- | ---------- |
| 小数据主结果：train=2000        | 0.852             | -              | 0.462        | 0.400    | -                   | 0.4084     |
| 完整训练数据 probe：train=49000 | 0.728             | 0.7296         | 0.614        | 0.611    | 0.1186              | 0.6894     |

扩大训练数据后，测试准确率从 `0.400` 提升到 `0.611`，验证准确率从 `0.462` 提升到 `0.614`。同时，完整训练准确率与测试准确率之间的差距约为 `0.119`，明显小于小数据主结果中的 gap。

这说明原先看似严重的过拟合，很大程度上来自快速验证子集的数据规模限制。扩大训练集后，即使不改变网络结构、不更换优化器、不加入数据增强，模型的泛化表现也明显改善。

不过，完整训练数据实验并不表示问题已经完全解决。`Test Acc=0.611` 仍然不高，说明三层 CNN 的表达能力、无数据增强、无 BatchNorm / Dropout、超参数未系统搜索等因素仍然限制了模型性能。

## 7. 后续改进方向

后续如果继续提升 `ThreeLayerConvNet` 的性能，应优先考虑以下方向：

1. 统一使用更完整的 CIFAR-10 训练设置，并同步重跑所有主要模型；
2. 增加数据增强，例如随机裁剪、水平翻转和轻量颜色扰动；
3. 在 CNN 中加入 BatchNorm 或 Dropout；
4. 使用验证集进行系统超参数搜索，而不是只进行单点 probe；
5. 整理 train / val 曲线，进一步判断是否需要 early stopping 或调整训练轮数。

## 8. 总结

本次补充分析说明，小数据主实验中 `ThreeLayerConvNet` 的 train-test gap 确实明显，但该现象很大程度上与 Assignment 2 快速验证设置中的训练数据规模有关。完整训练数据 probe 表明，只扩大训练集而不改变模型结构，就能将测试准确率从 `0.400` 提升到 `0.611`，并显著缩小训练集和测试集之间的差距。

因此，当前结果不应简单理解为实现失败，而应理解为：在快速验证子集上，模型容易出现泛化不足；当数据规模扩大后，泛化表现明显改善，但模型仍有进一步优化空间。
